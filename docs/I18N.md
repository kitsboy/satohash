# Internationalization — finish all seven languages

**Version:** 5.0.0-ELITE · **Updated:** 2026-09-13 · **Lane:** Grok / M3 (SPA). Kimi does **not** rebuild the API for copy.

Satohash ships **seven locales**. The goal is the **whole site** in those seven — not a new eighth language. **Do not add Arabic** until these seven are actually done.

| Code | Language | Native |
|------|----------|--------|
| en | English | English |
| es | Spanish | Español |
| fr | French | Français |
| de | German | Deutsch |
| pt | Portuguese | Português |
| sw | Swahili | Kiswahili |
| zh | Chinese | 中文 |

English JSON is the source of truth. `npm run i18n:check` must stay green: every new `en` key is mirrored in the other six files in the same commit.

## How it works

- App JSON: `src/i18n/translations/*.json`
- Marketing / pages: `src/i18n/marketing/{landing,faq,pages}.{lang}.json`
- Switcher: `src/components/forms/LanguageSwitcher.jsx` → `localStorage.satohash_lang` + `?lang=`
- Zero-JS proof card: `functions/p/proof-i18n.js` (`?lang=`, cookie, `Accept-Language`)
- SEO: `usePageMeta` writes hreflang alternates
- Gate: `npm run i18n:check` (`scripts/i18n-check.js`)

Keep in English on purpose: hash hex, `ots-cli`, calendar hostnames (`alice` / `bob` / `finney`), **Bitcoin**, **OpenTimestamps**, **Satohash**, protocol words **Pending** / **Confirmed**.

## Per-page recipe (cheap, repeatable)

1. Extract user-visible English → `pages.en.json` (or `translations/en.json`).
2. Copy keys into es/fr/de/pt/sw/zh and translate that slice only.
3. Wire `t('…')`. Do not drop CTAs or legal meaning.
4. `npm run i18n:check`.
5. Spot-check `?lang=es` on the page (desktop + one mobile width if layout changed).
6. **Commit and push** before starting the next page.
