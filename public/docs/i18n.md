# Internationalization

**Version:** 5.0.0-ELITE · **Updated:** 2026-09-13 · **Live:** https://satohash.io

Satohash ships **seven locales**. The language control is a single flag/code button in the nav — it opens a portaled panel that stays on screen on phones. The product goal is the **whole site** in these seven. A new language is not added until they are finished.

## Locales

| Code | Language | Native |
|---|---|---|
| en | English | English |
| es | Spanish | Español |
| fr | French | Français |
| de | German | Deutsch |
| pt | Portuguese | Português |
| sw | Swahili | Kiswahili |
| zh | Chinese | 中文 |

## How it works

- UI strings: `src/i18n/translations/*.json` plus marketing packs in `src/i18n/marketing/`
- Language switcher writes the locale and updates the URL (`?lang=`)
- `usePageMeta` + `src/seo/pageMeta.js` switch title/description per language
- Zero-JS proof cards (`/p/<hash>`) also follow `?lang=`, the language cookie, or `Accept-Language`
- hreflang targets are listed in the SEO docs
- `npm run i18n:check` fails if keys drift

## What is translated

**Done:** landing, FAQ, pricing, glossary, guides, legal headings, government marketing, the stamp → verify → proof-card loop, `/stamp/done`, counsel, status chrome, `/watch`, nav/footer, `/donate`, `/proof-pack`.

**Still English (next):** About, Pitch, Network, Explorer, Atlas, then remaining public marketing, then logged-in/admin screens.

Template **bodies** stay English-primary. Hash hex, `ots-cli`, Bitcoin, and OpenTimestamps stay in English on purpose.

## Adding a string

1. Add the key to `en` first.
2. Mirror it in the other six locale files (or the i18n check will fail).
3. Prefer `defaultValue` only as a last resort in JSX.
4. Commit and push that page before starting another.
